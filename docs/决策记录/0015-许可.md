# 0015. 许可：GPL-3.0-or-later

> 注（2026-10-11 追加）：本文里的 `tools/skirt/` 后来改成了 `skirt/`——
> 构建驱动独立成了一个机制，不再叫「工具」。正文保持原样。

日期：2026-10-10
状态：已采纳

## 背景

仓库一直是公开的，但**没有 LICENSE**。严格说这意味着没有人有权使用它——
连"这是开源软件"都算不上。

而且它挡着一件具体的事：Codeberg 的政策要求公开仓库必须有开源许可证。

## 这个仓库里有三种东西，它们的问题不一样

```
tools/skirt/          我们写的【真软件】      → 许可要管的主要对象
packages/*/spec.toml  配方（说明书）          → 可以很自由
packages/*/*.patch    补丁【是派生作品】      → 必须跟着上游 ✗
```

**第三条最容易被忽略**：`gzip` 的补丁改的是 GPL-3 的源码，所以那份补丁
**必须**是 GPL-3——不能因为我们想用 MIT 就把它变成 MIT。没有 LICENSE 的
时候，这属于未授权分发。

## 决定

**整个仓库用 `GPL-3.0-or-later`。**

## 理由

**1. 不能被闭源拿走。** 包管理器和构建工具是一个发行版的"宪法"——它决定了
这个系统怎么被造出来。如果它是 MIT，别人可以拿走、改个名、闭源、卖钱，
而这个系统是很多人的劳动。这也是为什么发行版的工具链几乎全是 GPL：

```
pacman (Arch)       GPL-2.0
dpkg / apt (Debian) GPL-2.0+
apk-tools (Alpine)  GPL-2.0
portage (Gentoo)    GPL-2.0
nix                 LGPL-2.1
```

**2. 和生态一致。** glibc 是 LGPL-3，bash / coreutils / gcc 是 GPL-3+。
我们的工具是这个世界的一部分。

**3. GPLv3 比 v2 多了两样要紧的东西**：显式的**专利授权**（v2 没有，所以
有人可以拿专利来告你），和**防 Tivo 化**（不能在锁死的硬件上跑 GPLv3 软件
而不给源码）。

**4. `-or-later`。** 上游将来升 v4，我们自动跟上，不用改 42 个文件。

## 代价（说清楚）

**不能被闭源产品内嵌。** 如果有人想拿 `skirt` 去做闭源商业发行版，GPL
不允许。**但那正是它存在的理由。**

## 一个已经在承担的义务

我们发布的镜像里有 GPL 软件（bash、coreutils、gcc），而 GPL 要求**分发
二进制时提供对应源码**。所以：

> 公开配方不是姿态，是**履行义务的方式**。

补上这个 LICENSE 只是把已经在做的事说清楚。这条也写进了 README。

## 关于内核的许可

Linux 内核是 **GPL-2.0-only**，和 GPL-3.0 不兼容——**但这不影响我们**：
用户态和内核是**聚合**关系，不是合并关系。每个发行版都同时分发 GPL-2 的
内核和 GPL-3 的用户态。

我们**分发**内核，不重新许可它。

## 考虑过但没选的

**配方用 MIT/CC0、只有 tools 用 GPL。** 理由很实在：配方是"怎么从零建一个
发行版"的知识，越自由传播得越广，而这符合项目 build in public 的立场。

**没选它，是因为一个许可比两个简单。** 不必现在为假想的用户复杂化——如果
将来有人明确说"我想把配方用在别处但 GPL 挡住了"，再拆也不迟。

**Apache-2.0。** 有专利授权这一点很好，但它允许闭源使用，和第 1 条理由冲突。
