# 0006 包管理器选型与中文支持

- **日期**：2026-10-10
- **状态**：**已决定**（实现待排期；apk 的 i18n 改造细节待看到源码后核实）
  - **注意**：apk 的中文是 0012 里的**唯一例外**——上游不接受，所以它是一条我们
    要长期维护的补丁，而不是一份可以提上去的贡献。现在搁置。
- **影响范围**：`minimal` 风味的构成、包格式、仓库结构、将来的 `server` 与 `desktop`

## 背景

`minimal` 风味的定位是「**能取代 Alpine 的容器基础镜像**」——能启动、能联网、**能装软件**。
没有包管理器的最小系统是个玩具，所以包管理器从「以后再说」变成了关键路径上的一环。

决策记录 0004 里留了一句「apk 部分待评估」，这份记录把它结掉。

## 决定

### 一、用 apk-tools

| 候选 | 体积 | 依赖链 | 中文 | 判断 |
|---|---|---|---|---|
| **apk-tools** | ~454 KB | **短**（openssl + zlib） | ❌ 零 i18n | ✅ **选它** |
| pacman | ~500 KB | 长（libarchive、curl、gpgme、openssl） | ✅ 有 | ❌ 依赖链对一个最小镜像太重 |
| 自己写 | — | 零 | ✅ 完全可控 | ❌ 事务、升级、文件冲突是真的难，而且是**偏离目标**的活 |

**选 apk 的核心理由：它是为极简系统而生的。** Alpine 的整个基础镜像（musl + busybox + apk）
才 7 MB。它二十年就干这一件事，而我们要的正是同一件事。

### 二、只借格式和工具，不借包

**我们和 Alpine 不共用任何二进制包。**

```
Alpine  musl  →  .apk 包里的 ELF 是 musl 链接的
我们    glibc →  互相装不上
```

共用的是 **`.apk` 格式**和 **apk-tools 这个客户端**。包本身各建各的。

（`.apk` 格式很简单：一个 tar，里面三个成员——签名、`.PKGINFO`、数据。这也是它适合被
自己掌控的原因之一。）

### 三、给 apk 补中文

**这是已知的唯一缺点，而且我们要自己解决。**

apk-tools **完全没有国际化层**——实测：

```
/sbin/apk           0 个 gettext 符号
libapk.so.3.0.0     0 个 gettext 符号
.mo 文件            0 个
apk-tools-lang      不存在
```

所以「加一个中文包」的真实含义是：**先给 apk 加 i18n 支持，然后才有翻译可言。**

做法：

| 步骤 | 难度 | 说明 |
|---|---|---|
| 包装输出函数 | 待核实 | apk 的消息走它自己的一小套打印函数（`apk_error` / `apk_message` 之类），包装点应该很集中。**具体多少处必须看到源码才知道**——GitLab 的 raw 接口挡了抓取，实现时核实 |
| gettext 初始化 | 小 | `setlocale` + `bindtextdomain` + `textdomain` |
| `po/` 基础设施 | 中 | `.pot` 生成、Makefile 接入、`LINGUAS` |
| 翻译本身 | **大，但可增量** | 见下 |

**三件让它不那么可怕的事：**

1. **gettext 天然支持部分翻译。** 没翻的字符串回落到英文，**不会坏**。所以可以从 20% 开始，
   慢慢补——而不是「翻完才能用」。
2. **作为补丁带着走，不 fork。** 就像 `gzip/fix-head-macro.patch` 那样，放在配方目录里。
   上游要是接受了更好，不接受也不影响我们。
3. **Alpine 自己就有 `-lang` 子包的约定**，我们的 `apk-tools-lang` 正好用刚设计的子包机制：

```
apk-tools-lang-3.0.0/
└── usr/share/locale/zh_CN/LC_MESSAGES/apk.mo
```

### 四、`minimal` 里还有哪些包

确认「SSL 和 curl 是 Linux 上几乎必不可少的东西」，所以：

```
perl  →  openssl 的构建系统（Configure）是 perl 写的，绕不开
      →  openssl  →  curl
                  →  apk-tools（apk 自己做 HTTP，不用 curl）
                  →  ca-certificates
```

**`perl` 只是构建依赖，不进 `minimal`。** openssl、curl、ca-certificates、apk-tools 进。

## 后果

**拿到：**

- 一个依赖链很短、为极简而生的包管理器
- `minimal` 真的可以「装软件」，真的可以作为 Alpine 的替代（在 glibc 这一侧）
- 中文支持是**我们自己加上去的**——这本身就是对上游的贡献，也可能被接受

**代价：**

- 要维护一个 i18n 补丁，直到上游接受（或者永远）
- 翻译是长期活，不会一次做完
- 采用了别人的包格式，将来想改格式要先说服自己不值得
