# 0014 子包与拆分的时机

- **日期**：2026-10-10
- **状态**：**已决定并已实现**
- **影响范围**：所有配方可用的 `[[subpackage]]`、`collect` 阶段、拼装期的筛选

## 背景

`base` 一开始是 86.9 MB，比 `debian:stable-slim` 大两倍。拆开看，**glibc 一个
包占了 57 MB**，而里面大部分是编译时才需要的东西：

```
libc.so.6 + ld-linux + 其他 .so.6      4.1 MB   运行时必需
.a 静态库                              7.2 MB   只有编译需要
/usr/include 头文件                     3.3 MB   只有编译需要
/usr/share/i18n locale 源数据          16.1 MB   只有 localedef 需要
```

再加上后来生成的语言数据（62 种语言、29.6 MB）和三个 locale，`base` 一度到
122.9 MB。

## 决定

### 一、拆分发生在**收集阶段**，不在构建阶段

```toml
[[subpackage]]
name        = "glibc-dev"
description = "glibc 开发文件：头文件、静态库、链接脚本、locale 源数据"
files = ["usr/include/", "usr/lib/*.a", "usr/share/i18n/"]
```

构建脚本照旧把一切装进 `$PKGDEST`，只有收集时决定每个文件归谁。

**为什么这很重要**：调整拆分规则**不用重编**。glibc 重编一次 8 分钟，而
「`usr/share/i18n` 该不该算开发文件」这种问题，答案是试出来的——把试错成本
从 8 分钟降到 1 秒，这件事才做得动。

### 二、子包就是普通包

```
output/aarch64/glibc-2.44-1/
output/aarch64/glibc-dev-2.44-1/
output/aarch64/glibc-locales-2.44-1/
```

下游（拼 rootfs、依赖解析、打包）不需要知道子包的存在。子包依赖母包，而
拼 rootfs 只跟 runtime 依赖——**所以 `glibc-dev` 永远进不了成品系统，这是
自动的**，不需要额外规则。

### 三、`recipe_of` 是新增的一层，凡是「按名字找配方」都得过它

子包没有自己的目录，只靠名字在 `output/` 和依赖里被找到。

**这是本次改动里最容易出错的地方**：实现过程中它引出了三个 bug，全都是
某处直接 `load_spec(名字)` 而名字是子包——`source_date_epoch`、`assemble`
的时间戳、还有 `Path.is_dir()` 跟随符号链接导致的分流统计错位。

### 四、拼装期的筛选和子包是两件事

```
子包       结构性的拆分，包管理器需要它      glibc-dev 不进 base
拼装期筛选 每个风味自己决定要什么            62 种语言只留 2 种
```

语言筛选放在拼装期而不是给每个包拆 `-lang` 子包，理由和第一条一样：**可逆**。
包里一个不少，只是拼出来的系统不带。以后想放进去改一行，不用碰 23 个配方。

### 五、只搬真正占体积的东西

`/usr/lib` 下有一批不带版本号的 `.so`，是链接期的符号链接——但里面混着两个
真的 ELF（`libmemusage.so`、`libpcprofile.so`，`LD_PRELOAD` 用）。**模式匹配
没法区分「符号链接」和「真 ELF」。**

它们合计不到几 KB，所以留在主包里，不写那条规则。**宁可少省几 KB，也不要
写一条会误伤运行时的规则。**

## 安全检查：一个文件都不能丢

收集时逐个文件核对归属，有文件没归处或有重复立刻报错。

```python
if placed != seen_files:
    die("收集时文件归属不一致：...")
```

**这条检查当场就抓到了两个真 bug。** 分流错了的后果很隐蔽——文件不会消失，
只会跑到另一个包里，然后产出一个「装得上、跑不起来」的系统，等到运行时才
暴露。

## 结果

```
glibc          66.8 MB → 31.0 MB     （运行时）
glibc-dev                28.0 MB
glibc-locales             9.0 MB

base  122.9 MB → 17 MB（tar.gz，含中文）
      debian:stable-slim 是 28.8 MB
```

## 还没做的

- **`/usr/share/man` 的 4 MB**——对容器基础镜像是纯浪费，属于同一类拼装期开关
- **别的包的 `-dev`**——`/usr/include` 还剩 1 MB、静态库 1 MB，不值得拆
- **英文之外的语言**——筛选列表目前写死在 `KEEP_LOCALES`，以后该由风味决定
