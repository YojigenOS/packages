# 0023 什么算「可信源」—— 0022 那条规则的边界

**2026-10-21 定。** 而它是 0022 的**补丁**，不是 0022 的替代。

## 0022 留下的那个洞

0022 说：**有官方二进制的就只分发，不编译。**

而"官方"没定义。于是当 `python3` 那个 253 MB、编译 2 分 17 秒的包变成负担时，
自然的问题是：**能不能拿一个现成的 CPython 二进制树？**

候选是有的，而且很成熟：`astral-sh/python-build-standalone`
（`uv python install` 用的就是它）。实测它有 `3.14.8` 的

    cpython-3.14.8+20261020-x86_64-unknown-linux-gnu-install_only.tar.gz    72 MB
    cpython-3.14.8+20261020-aarch64-unknown-linux-gnu-install_only.tar.gz   55 MB

**而 python.org 不发 Linux 二进制**：`ftp/python/3.14.0/` 里只有
`Python-3.14.0.tar.xz` / `.tgz`（源码），`.deb` / `.rpm` 数量是 **0**；
`amd64/` `arm64/` 那两个目录是 **macOS 的 `.pkg`**。

## 决定

**「可信源」= 上游项目自己发布的二进制。**

具体三条，缺一不算：

| # | 判据 | 例子 |
|---|---|---|
| 1 | 发布者是上游项目**本身**（域名 / 账号属于它） | `static.rust-lang.org` · `nodejs.org/dist` · `go.dev/dl` |
| 2 | 有可校验的摘要，而摘要来自**同一个发布渠道** | 同一页面上给的 sha256 / 签名 |
| 3 | **那个平台必须有官方二进制** —— 没有就我们自己建 | `python.org` 不发 Linux → python 自己建 |

★ **第三方重新编译的二进制，再流行也不算。** 包括
`python-build-standalone`、`conda-forge`、发行版的 `-bin` 包。

## 为什么

不是"不信任 Astral"。是**信任边界要说得出是一句话**：

    这个二进制是【上游】发的

而第三方代庖之后，那句话会变成：

    这个二进制是【某个第三方】从上游源码重新编的，而我看过它的配方

★★ 第二条在技术上是可验的，而它**不是同一件事**。0022 的全部价值在于
「盘上哪些东西是借的，而借的是谁的」这件事**过一年还能回答**。第三方代庖
一旦开了口，那个答案会退化成一串"某某项目重新编的"——而那和"我们自己编的"
在可追溯性上差别很小，**却少了「我们自己的构建环境」这个前提**。

★ 更实际的一条：第三方预编译树的前缀是它的（`python/`），搬到 `/usr` 之后
`sysconfig` 里烤死的路径、`.so` 的 rpath、shebang 全要处理。**"能用但不干净"**
的东西在构建环境里会长期咬人。

## 推论

| 包 | 上游有官方 Linux 二进制吗 | 结论 |
|---|---|---|
| `python3` | **没有**（python.org 只发源码） | **永远自己建。** 253 MB 靠按 0014 拆子包解决，不靠换源 |
| `rust` | 有（`static.rust-lang.org`） | 可以只分发 |
| `node` | 有（`nodejs.org/dist`） | 可以只分发 |
| `go` | 有（`go.dev/dl`） | 可以只分发 |
| `docker` 之类 | 有（各自官方） | 可以只分发 |

★★ 所以 0022 要的"第一个分发包"候选里，**`python3` 出局**。剩下的是 `rust` /
`node` / `go` 那一类——它们的源码构建是几小时，而官方二进制是给**别的 glibc
发行版**编的，正好用来验 0022 那套判据（`ldd` 里有没有我们没有的库 +
`--version` 能不能跑）。

## 而它顺手划清的另一件事

**"可信源"只管【二进制】。源码的源是另一回事**（见 `docs/待办.md` §1.5.Bi：
90 个配方里 89 个只有 0 或 1 个源）。那边要的是**多个镜像、同一个 sha256** ——
而"谁编的"这条不适用，因为源码是我们自己编的。
