# 0010 上游测试

- **日期**：2026-10-10
- **状态**：**已决定**（实现待排期；具体哪些包用哪个级别待定）
- **影响范围**：所有配方的 `[build]` 段、构建时长、`skirt` 的构建流程

## 背景

**23 个配方，没有一个跑过上游的测试套件。** 编完就装、装完就 strip。

平常这也许可以拖，但**我们最近动的全是会改变行为的开关**：

```
--enable-default-ssp      改了编译器的默认值
-g0                       改了调试信息的生成
LC_ALL=C.UTF-8            改了区域环境
-Wl,-dynamic-linker 路径   只在 aarch64 是对的
locale 拆不拆             影响依赖 locale 的程序
```

**这些改动会不会弄坏什么，上游的测试套件本来就能告诉我们。** 现在它们已经装进
产物了——所以「晚了」指的不是工作量，是**那些改动已经出了门**。

## 决定

### 一、`[build] check` 三级

```toml
[build]
type      = "autotools"
configure = ["--prefix=/usr"]
check     = "required"     # 或 true / false
```

| 值 | 行为 | 用在哪 |
|---|---|---|
| `"required"` | 失败**中止构建** | 少数关键包 |
| `true`（默认） | 跑，失败**警告但不阻止** | 大多数包 |
| `false` | 不跑 | 见下 |

### 二、什么情况用 `false`

- **`gcc`**——测试套件一小时以上，而且它测的是编译器自身，我们已经用别的包
  间接验证了它
- **纯数据包**（`tzdata`、`filesystem`、`ca-certificates`）——没有可测的东西
- 那些**测试套件本身有问题**的包——但要写清楚为什么，不能默默关掉

### 三、按构建类型选择测试命令

```
autotools  →  make check
cmake      →  ctest --output-on-failure
meson      →  meson test
custom     →  配方自己声明
```

### 四、测试输出要落盘

失败而不留证据等于没跑。输出存到构建目录里，和日志放在一起。

## 依据

| 项目 | 做法 |
|---|---|
| **Debian** | 构建时跑，失败记录但不阻止 |
| **Arch** | `check()` 可选，`makepkg --nocheck` 跳过 |
| **Alpine** | `abuild` 的 `check()`，可选 |
| **Gentoo** | `FEATURES=test`，**默认不开** |
| **LFS** | **明确列出哪些测试值得跑** |

**LFS 那条最实用**：它承认了一个不舒服的事实——不是所有上游测试都值得跑。所以
我们的默认是「跑但只警告」，而不是「跑且必须过」。

## 后果

**拿到：**

- 我们自己那些改动（加固、`-g0`、locale、`LC_ALL`）的**第一道真实检验**
- 上游测试是一种**独立于我们的**验证——不是我们自己写测试自己过
- 出问题时，测试日志能指向具体是哪个功能坏了

**代价：**

- **构建明显变慢。** glibc 的测试十几分钟，coreutils 几分钟。全量构建可能从
  一小时变成两小时以上
- 上游测试会有**假失败**（环境、flaky、已知问题），需要维护一份「已知失败」的
  记录，否则告警会被忽略——而一旦被忽略，就等于没跑

## 还没定

- **哪些包用 `"required"`。** 倾向 glibc、bash、coreutils，但要先看它们实际跑多久、
  失败率如何
- **glibc 的测试要不要跑全部。** 它有一些测试需要特殊环境
- **测试失败时算不算「这个包构建成功」。** 影响 CI 的红绿
- 第一次跑的时候会有多少假失败——**这个只有跑了才知道**
