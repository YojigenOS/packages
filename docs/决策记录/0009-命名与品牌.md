# 0009 命名与品牌

- **日期**：2026-10-10
- **状态**：已决定（版本代号的具体风格待定）
- **影响范围**：`os-release` 的字段、镜像 tag、文档与对外的说法

## 来历

```
YojigenOS   四次元   ← 系统的名字
skirt       短裙     ← 构建工具的命令名
```

原话是：**「美少女的短裙下面，是四次元空间，不能随便看，也不能随便摸，
是神秘的、充满吸引力的地方。」**

这不是硬凑的比喻——它**精确对应了两个技术决定**：

| 比喻 | 技术上的对应 |
|---|---|
| 四次元空间 | **容器的私有文件系统**。构建发生在容器自己的文件系统里，不是宿主的（见 0002）。那是一个和外面隔开的维度 |
| 「不能随便看，也不能随便摸」 | **构建环境是封闭的**。除了声明过的依赖，什么都不会从外面漏进去 |
| 「伸手进去取东西」 | `skirt build <包>` 本身就是那个动作——从那个空间里把编译好的东西掏出来 |

### 它和可复现构建构成一个对照

```
里面看不见   →  用户不需要知道构建过程
拿出来的能验  →  但可以验证产物（见 0005：冷热构建逐位一致）
```

**「你看不见里面，但你能验证拿出来的东西」——这正是一个发行版该有的样子。**

## 对外的观感

**「四次元口袋」是哆啦A梦的梗**，所以对外它是动漫式的俏皮，不是别的什么。

- 命令名 `skirt` 是英文、含义中性
- 中文那层联想只有懂的人懂——**它是彩蛋，不是招牌**

这个分寸和 Debian 用《玩具总动员》角色命名是同一种做法：内部有故事，对外只是
个好记的名字。

## 版本代号

想用**二次元美少女的名字**给版本起别称。三个方向：

| 选项 | 风险 | 二次元浓度 | 说明 |
|---|---|---|---|
| 直接用动漫角色名 | 低 | 满 | 先例充足，但名字不属于我们 |
| **日本神话 / 传说** | **零** | **很足** | 公有领域。**而且动漫本来就大量取材于此**——对受众来说一样「很二次元」，却没借任何人的 IP |
| 原创少女名 | 零 | 取决于起得如何 | 完全属于我们，能形成自己的谱系 |

### 关于风险的分寸

涉及的是**商标**，不是版权。

- **版权**：角色**名字**本身一般不受版权保护（版权保护表达，不保护名字）
- **商标**：但角色名**可以**被注册（例如「初音ミク」是 Crypton 的注册商标）

**Debian 的先例**：从 1996 年起用《玩具总动员》的角色名做代号，从没申请过授权，
Pixar/迪士尼也从没追究。但要注意他们的分寸——**只用名字**，不用角色形象、不用
原画、不用字体、不拿它当产品名。代号是技术性的，不是招牌。

**风险等级**：非商业开源项目、只用作代号、不涉图像 → 低。但只要沾上捐赠或商业
活动，就往上走一格。

**倾向第二个方向**（神话）：神话名字之所以「二次元」，正是因为动漫一直在用它们。
所以天照、月読、玉藻、不知火、雪女这类名字，读者看到会自动代入那个气质——
**而没有人能来说这是他的。**

## 技术上放哪

`os-release` 里早就留好位置：

```ini
VERSION="2026.10（辉夜）"      ← 给人看
VERSION_CODENAME=kaguya       ← 给脚本看
```

**代号也可以当镜像 tag**——Ubuntu 就是这么干的（`ubuntu:24.04` = `ubuntu:noble`）。
所以将来可以是：

```
yojigenos/minimal:2026.10
yojigenos/minimal:kaguya      ← 同一接口的别名，符合 0003「tag 是接口」
```
