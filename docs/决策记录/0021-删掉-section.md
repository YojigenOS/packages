# 0021 删掉 `section`

- **日期**：2026-10-15
- **状态**：**已决定**
- **影响范围**：87 个配方的 `[package] section`、`collect.py` 写进 `meta.json`
  的那一项、以及以后所有新配方

## 背景

`section` 是每个配方 `[package]` 里的一个字段，一路写进 `meta.json`
（而那跟着 `.apk` 走，用户看得见）。它现在有十个不同的值：

```
devel 18 · libs 17 · base 14 · utils 13 · core 10 · net 7 · system 4
lib 1 · util 1 · （而 87 个里另有 2 个根本没有这个字段）
```

`配方约定.md` 里早就写过它该删（"为什么 `section` 字段要删"那一节），
而那一节的理由是对的，只是**没有人去执行**。这一篇把它定下来。

## 决定：删掉

### 理由一：那些值混了【两个轴】

```
libs · utils · net · system        ← 「它是什么」
base · core · devel                ← 「它在哪个镜像里」
```

而**两个轴都已经有别的出处了**：

```
「它是什么」  →  recipes/<类>/ 那个目录名。它就是 kind，而且【只有一处】
               （见 0001 那一族：一处信息一处。spec.py 的 kind_of() 直接读目录）
「它在哪个镜像里」→  distro/variants/<风味>.toml 的那张包列表
```

★ 所以 `section` 是这两个事实的**第二份**，而且是**混在一起**的第二份。

### 理由二：它已经漂了

- **两个手误**：`libs` 17 个里夹着一个 `lib`；`utils` 13 个里夹着一个 `util`
- **两个缺失**：87 个配方里有两个没有这个字段
- **`base` 那个值最有说服力**：14 个配方写着 `section = "base"`，
  而 `variants/base.toml` 里是 **15** 个包 —— 两个数字对不上，
  因为它们的轴不同（一个是"分类"，一个是"进哪个镜像"），
  而**看起来像同一个东西**。这正是"两处不一致"最坏的样子：
  它不报错，它只是让人得出错误的结论。

### 理由三：留着它就会有人用它

这是 `配方约定.md` 里那句话，也是这次真正的原因：

> **一处信息只该有一处。** 留着它就会有人用它，然后两处不一致。

一个字段只要存在，就会有人拿它做判断（做一个包列表页面、给 `apk search`
分组、写文档）。而那时它的第二个轴会开始和 `variants/*.toml` 打架 ——
**而打架是静默的**。

## 而"要不要留一个【纯分类】的字段"

考虑过：把 `base`/`core` 那些去掉，只留 `libs`/`utils`/`net` 这一轴。

**否决了**，因为那一轴就是 `recipes/<类>/` 的目录名 ——
再写一份到每个配方里，是同一个事实的第二个出处，而**没有任何好处**：
读的人要读目录名的话，目录名就在路径里。

★ 而"分类"这件事本身是**需要的**（`kind_of()` 在用、`test_kind.py` 在查），
  只是它的出处**已经定死在目录名上了**。所以这里删的是一个**重复**，
  不是删掉那个概念。

## 怎么删

1. 87 个配方里的 `section = "…"` 一行删掉
2. `collect.py` 里那三处（读主包、读子包、写 `meta.json`）删掉
3. 加一条测试：**任何配方里都不许再有 `section`** —— 否则它会悄悄长回来
4. 而 `meta.json` 少一项，所以 `.apk` 会变、`build_key` 会变

## 和别处的呼应

- `0001`（库路径布局）那一族说的是同一件事：**一处信息只该有一处**
- `0014`（子包拆分）用的判据也是这个
- 而这一篇是它的第三次应用，也是**第一次用在"删掉一个已经有了的字段"上** ——
  前面几次都是"别新增第二个出处"

## 而这条最值得记的是

**文档早就论证过了，而且论证是对的 —— 只是没有人去执行。**

一个写在约定里、而 87 个配方一个都没改的事实，会让人以为"约定不是真的"。
所以从这一篇起，凡是能写成检查的约定，**都配一条会红的测试**。
