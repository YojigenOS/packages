## 二、和 Fedora Server 的差距

拿 Fedora 43 的 `comps`（core 44 + standard 74，去重 114 个）逐条对照：

    有对应物    51 个
    概念不同   55 个（rpm/selinux/plymouth/dnf5/anaconda…）
    真缺        8 项

而那 8 项里：

    NetworkManager   ← 我们有 dhcpcd（职责对应，不是缺）
    iproute          ← 我们的包叫 iproute2（同一个东西）
    wget2-wget       ← 我们的包叫 wget（同一个东西）
    hostname         ← util-linux 提供（实测 TX 上 `hostname` 不工作，
                        但这个属 util-linux 的问题，不是"缺包"）
    compsize         ← btrfs 专用（我们不用 btrfs）
    words            ← /usr/share/dict/words（英文单词表，中文优先用不上）
    mailcap          ← MIME 类型表（很小，该补）
    at               ← **真的没有**（atd 定时任务，标准工具）

★★ **所以"基础包要全"这条已经基本做到了**：真缺的只有 2 个
   （`at` 和 `mailcap`），其余是别名或概念差异。

## 四、还没做的（按风险排序）

### 高风险：内核 CONFIG_MODULES

`kmod` 包建了、systemd 的 `+KMOD` 也开了，但**内核是 `CONFIG_MODULES=n`**
—— 所以 `modprobe`/`lsmod` 在 TX 上是空转的（`/proc/modules` 不存在）。

改它要同时：

    ① config.fragment 里 `CONFIG_MODULES=y`
    ② 把关键驱动**钉死 =y**（ext4 / virtio / ata / serial / overlay）
       —— 否则它们会从 =y 变成 =m，而模块放哪、谁加载、没 initramfs 怎么起，
          是一整类新问题
    ③ 重建内核 + 重建 devel 镜像

**而这是不可逆的**：改错了 TX 重启就起不来。所以它要单独一轮，且要有
回退方案（GRUB 里保留旧内核条目）。

### 中风险：还没补的真缺

    at         atd 定时任务（+ at 命令）
    mailcap    MIME 类型表

### 低风险：功能还关着的

    systemd -Dlogind=false    → 没有会话管理（单人服务器暂时不影响）
    systemd -Dnetworkd=false  → 我们用 dhcpcd，重复，不需要
    systemd -Daudit=false     → 没有 libaudit
    systemd -Dselinux=false   → 没有 SELinux 策略

    ★ 这几个是"没有对应依赖"或"职责重复"，不是遗漏。

## 五、一条方法论

**盘点要用机器可读的定义**（`comps`），不是看文档说"装了这些"。

而对照之后最有价值的一步是**把"缺"分成"真缺 / 别名 / 概念不同"三类** ——
114 个对 51 个看着差距大，分完之后真缺 8 个，再分完是 2 个。

★ 这和 0026 那条是同一个方法：**先分类，再判断**。
  不分类的话，"缺 47 项"会一直是个吓人的数字。
