## 六、还剩下的

### 内核 CONFIG_MODULES —— 唯一没做的

`kmod` 包建了、`+KMOD` 开了，而内核是 `CONFIG_MODULES=n`，所以
`modprobe`/`lsmod` 在 TX 上**空转**（`/proc/modules` 不存在）。

而它不是"加一行配置"那么简单。实测 `CONFIG_MODULES=n` 的真实含义是：

    defconfig 里 =m 的项 → **能内建的变 =y，内建不了的直接消失**

实测消失的：`IP_NF_FILTER` `IP_NF_NAT` `XFS_FS` `BTRFS_FS` `TUN`
`WIREGUARD` `BT` `KVM` —— 而 `BRIDGE` `SCSI` `USB_STORAGE` `WLAN`
变成了 `=y`。

★★ **所以 `=n` 不是"全功能"，是"能内建的都内建，内建不了的砍掉"。**

改它要同时：

    ① config.fragment 里 `CONFIG_MODULES=y`
    ② 把关键驱动**钉死 =y**（ext4 / virtio / ata / serial / overlay）
       —— 否则它们从 =y 变成 =m，而"模块放哪、谁加载、没 initramfs
          怎么起"是一整类新问题
    ③ 重建内核 + 重建 devel 镜像

而这是**不可逆的**：改错了 TX 重启就起不来。所以要单独一轮，
且要有回退方案（GRUB 里保留旧内核条目 —— 0025 已经证明那条路可用）。

## 七、这一轮的方法论

### 判据必须是"它能用吗"

`at` 的八个坑里，**没有一个**是被编译或打包发现的：

    编译通过 ✓  打包成功 ✓  安装成功 ✓  `at` 能排任务 ✓
    而任务永远不执行 ✗

唯一的判据是**排一个任务、等一分钟、看它跑没跑**。

### 而验证工具本身要先验证

0027 记过了：在 TX 上用 `nm`/`strings` 检查符号，而那两个命令不存在，
`2>/dev/null` 把 "not found" 吞成了"没有输出"，于是三次改错方向。

### 分类比数量重要

114 个对 51 个看着差距大。分成"真缺 / 别名 / 概念不同"之后，
真缺是 8 个，再分完是 2 个。**不分类的话那个数字会一直吓人。**
