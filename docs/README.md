# 文档

分四层。**分层的依据是「你会多久读它一次」**，不是主题。

| 目录 | 是什么 | 什么时候读 |
|---|---|---|
| `约定/` | 规矩。改配方、改结构之前必须遵守 | 动手之前 |
| `指南/` | 怎么做某件事。步骤和原因 | 做那件事的时候 |
| `记录/` | 发生过什么。按时间或按主题的日志 | 排查、或想知道"为什么当初这么定" |
| `决策记录/` | **不可变**。一篇一个决定，带日期 | 想知道某个选择为什么是那样 |

## 为什么要有「记录」这一层

原来没有，于是三种东西混在一起：**要遵守的规矩**、**要照做的步骤**、
**当时怎么查出来的**。结果是最大的一篇叫「自举」，678 行——想找"自举的
顺序是什么"要在里面翻，而那些按日期的排查过程才是 500 行的大头。

分开之后：

```
指南/自举.md        143 行   ← 自举是什么、顺序是什么、产物丢了怎么办
记录/自举历程.md    546 行   ← 怎么走通的、卡在哪、怎么定位的
```

**记录不是垃圾。** 里面的排查方法会复用——比如"怎么确认一个 bug 是上游的"
"怎么从构建卡在某个包定位到真正的原因"。所以它值得留着，只是不该和规矩
放在一起。

## 决策记录是不可变的

`决策记录/` 下的每一篇**正文永远不改**——它们记的是当时的事实。
（原来这里写着一个篇数，而它早就对不上了。写死数字的东西都会过时，所以改成不写。）

所以里面的路径会过时（比如 `tools/skirtlib/` 现在是 `skirt/skirtlib/`）。
处理办法是**在标题下【追加】一行说明**，不是回改正文。已经加过的四篇在
[`约定/仓库结构.md`](约定/仓库结构.md) 里列着。

